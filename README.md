# FeedRelay

将 YouTube 频道与指定邮件的更新，持续送达飞书的个人资讯订阅器。

> 当前状态：仅完成产品与技术设计，尚未开发。本文中的功能、版本与指标均为计划，不代表已实现或经过真实联调。
>
> 设计基线：2026-10-16。FeedRelay 是暂定工作名称，未进行品牌与名称可用性核验。

## 产品边界

核心流程：添加订阅 → 发现更新 → 去重保存 → 飞书通知 → 查看原内容。

- YouTube：先获取标题、简介、发布时间和视频链接，不默认下载视频或提取字幕。
- 邮件：只处理指定邮箱文件夹中匹配规则的 Newsletter，不作为通用邮箱客户端。
- 飞书：首版默认一个群机器人接收目标，提供发送状态和失败处理。
- AI：不是运行前提；后续按需接入 Sift，不因摘要失败而丢弃更新通知。
- 部署：单用户自托管优先，不建设公开多人 SaaS，不强行包装成 Agent。

Sift 继续负责“提取一份内容”；FeedRelay 负责“持续发现一批来源的更新”。两个项目独立，不修改 Sift，也不依赖 CasePilot 服务。

## 现在不做什么

- 不生成应用代码、依赖清单、数据库、容器或真实环境配置。
- 不安装依赖、不启动服务、不接邮箱、不创建飞书机器人、不发送消息。
- 不复制其他项目的 Key、邮箱授权码、App Secret 或 Webhook。
- Git 仓库用于托管当前设计文档；应用开发、部署和正式发布仍由后续明确任务决定。

## 开发前需落实

1. 确认运行服务器及其对 YouTube、邮箱和飞书的实际网络可达性。
2. 确认邮箱服务商、只读接入方式、文件夹和真实匹配规则。
3. 确认飞书接收方式：默认群机器人；若要应用机器人私聊，先更新设计。
4. 明确允许处理的真实数据与测试消息目标；任何模型或付费转写调用另行授权。

这些未知项不妨碍先写无凭证的自动化测试，但真实接入前必须落实。

## 开源方式

计划提供自托管应用、脱敏样例、部署说明与验证记录，不提供共享私人邮箱或公共免费转写服务。自身代码许可证拟采用 MIT，正式发布时确认；复用第三方代码须单独核验许可证并保留必要声明。

# 版本与开发计划

更新：2026-10-16。v0.1 候选版已实现，合成自动化与浏览器交互验证见 QUALITY_AND_RISKS。真实163/飞书接入和7天试运行未完成；本机公共 YouTube RSS 直连失败。

2026-10-17：按用户要求开发 v0.2 候选版，日报、公共 RSS/Atom、导入导出已实现；不因此将 v0.1 的真实联调和长期运行门槛标为完成。

## 1. 执行原则

版本按可验证能力划分，不预先承诺固定工期。阶段标为完成必须同时有实现、自动化验证和对应证据，不能只完成界面或改文案。

来源与消息连通性未知不会阻止写合成测试，但会阻止宣称真实闭环已经完成。失败与未知结果都要记录，不能以改预期值的方式让验收通过。

## 2. 版本总览

| 版本 | 产品结果 | 明确不包含 | 发布门槛 |
| --- | --- | --- | --- |
| v0.0 | 设计文档可用于后续开发 | 任何业务开发和服务接入 | 文档链接、需求/测试映射、范围与待确认项完整 |
| v0.1 | 频道/邮件更新可持久化并送到飞书私聊 | 每日汇总、通用 RSS、模型摘要、群聊、多租户 | M1-M5 完成，必要测试与真实小范围联调、7天试运行有记录 |
| v0.2 | 日报降低打扰，来源可迁移 | AI、跨邮箱自动去重、公开 SaaS | 汇总窗口、重启、迟到内容、重复发送与导入安全通过验证 |
| v0.3 | 明确预算下可选调用 Sift | 模型自主操作邮箱、交易建议或自动改变订阅 | 费用、摘要忠实度、降级、来源与外发授权验证 |

v0.1 的 M1-M4 可以形成内部候选版本，但 M5 结束前不宣称为稳定发布。

## 5. v0.3：Sift 可选增强

需求：FR-16。

- [ ] 明确何时总结：用户按需，或在预算内对指定来源自动执行，默认关闭。
- [ ] 说明摘要使用的正文范围、字幕来源、哪些数据发送给外部服务，并获得授权。
- [ ] 建立受控 Sift 接口、超时、内容哈希/模型/提示版本缓存和完整请求预算。
- [ ] 失败只影响摘要，不阻断已有更新提醒；推送重试不重复生成摘要。
- [ ] 用固定案例检查事实、关键数字、信息日期、原文观点和引用支持，不仅检查 JSON 或引文是否存在。
- [ ] 真实视频转写与模型请求先限定数量和费用；费用未知时不自动启动付费任务。

出口：用户能区分原始预览、AI 摘要和完整原文；预算触顶能停止，错误内容可追溯。没有全文时绝不按标题编造“完整视频总结”。

## 6. 范围变更与完成记录

每个开发任务记录：需求 ID、变更内容、对应测试、模拟/真实数据范围、执行结果、未解决风险。只有实际完成后才勾选任务。

新增来源、新消息渠道、多用户或框架替换均先记录原因、版本、数据权限和验收影响，再决定是否开发。不要以学习或面试包装为由绕过产品边界。

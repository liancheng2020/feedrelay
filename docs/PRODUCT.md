FR-25（2026-10-18）：摘要消息只展示内容标题、编号主题与简短总结，不附引文、链接、重复概括或提示尾注；网页保留原文定位。新建推送快照使用新格式，已发送及已冻结快照仍按原记录展示。

FR-26（2026-10-18）：视频摘要采用独立资讯简报表达，直接提炼结论、依据与限制，避免“字幕梳理/转写显示/视频介绍”等过程导语。预测、估值和投资判断保留作者归属，来源类型在界面单独展示。修改文风不删历史结果、正文缓存或用量记录。

FR-27（2026-10-18）：最近更新各条目提供删除图标；先展示标题与影响，取消不写入，确认后移除列表记录、清理正文/摘要、停止未发投递。保留去重标记与用量账本，已发送消息不能撤回。含该条目的已冻结日报分片停止发送，不静默改写已冻结内容。手机端同样可删除。

字幕定义：可读取的YouTube CC轨道与画面内嵌文字不同；抓取为空不宣称所有视频无字幕。详情明确区分平台字幕与本地音频转写，模型要点附原文定位片段供核查，不将片段存在作为语义准确性保证。

## 1. 定位与价值

FR-24（2026-10-17）覆盖旧无ASR约束：详情“生成视频摘要”依次尝试公开字幕、无/空字幕时本地音频转写、DeepSeek全文提炼与时间证据。仅在本机显式开启ASR并确认外发范围后处理；不读浏览器Cookie、不绕过登录、不下载画面、不新增付费转写服务。转写文字与平台字幕明确区分；展示提取/转写/总结阶段，缓存全文以免模型重试重复转写。超时/超长/下载受阻明示，不以简介或局部抽样冒充全文。音频仅用临时目录，结束清理；ASR可能误识别，不保证画面理解或语义准确。沿用原累计模型账本与推送，不新建队列或独立后台。

FR-23（2026-10-17）：YouTube详情不展示发布者简介/推广，只保留视频和已获取的字幕原文；详情按需生成固定使用字幕，不提供简介替代入口。邮件/RSS正文仍展示，来源配置保留既有兼容。无/空字幕展示“暂无可用字幕”，网络/风控等展示“字幕获取受阻”，与模型生成失败区分；可显式重新获取，来源阶段受阻不调用模型、不自动ASR或编造正文。列表和详情采用一致的状态文案，底层失败记录不被抹除。

FR-22（2026-10-17）：个人阅读优先，最新更新采用紧凑表格（标题、来源、摘要/投递状态、内容时间），点击进入可刷新/返回的独立详情。详情区分视频简介与已获取字幕，直接使用DeepSeek生成带原文引用的摘要，不再依赖外部Sift源码。摘要支持要点、脉络图与时间定位；不从不存在的数据虚构统计图。手动“微信/飞书推送”只向当前活动通道发送最新有效摘要，明确确认、同版本幂等排队；不重新生成、不双发、不自动外发旧结果。保留预算、引用核查与未知结果人工处理。点击生成前确认本条正文范围，按需授权不隐式开启来源自动摘要。旧实现/目标变更后须重新确认预算，不清零累计账本。本轮最多3次已获授权的公开视频模型请求，计入既有剩余额度；无私人邮件读取授权。

FR-21范围调整（2026-10-17）：优先个人使用，增加微信ClawBot为可选私聊接收端，飞书代码保留；一次只启用一个通道。首版仅扫码绑定、绑定人入站上下文更新、纯文本测试/通知/摘要，复用现有队列。不得用其他微信联系人消息更换接收人；不安装完整OpenClaw，不处理微信指令、群聊或媒体。扫码与短期发送、无互动隔夜/24/48小时推送分别验收；未验证前不承诺长期主动触达。

FeedRelay 是单用户自托管的资讯订阅与推送工具，将 YouTube 频道和指定邮件的更新统一送到飞书。

核心问题不是“生成更多摘要”，而是减少反复打开频道和邮箱检查更新的动作，让用户知道新增了什么、是否值得看、去哪里查看。

### 1.1 主要用户

- 关注若干 YouTube 频道，并订阅财经、技术等 Newsletter 的个人。
- 日常使用飞书，希望自行掌握数据与服务凭证。
- 愿意部署一个轻量服务，不要求开箱即用的公共托管 SaaS。

首个真实使用场景是指定新闻邮件（当前用户提到的美投网）与少量 YouTube 频道。该品牌只是可配置示例，不是代码中的特殊业务分支。

### 1.2 产品承诺

在来源可达、服务运行与配置有效的前提下，增量发现来源公开提供或邮箱实际接收的内容，保存处理记录，尽力可靠推送。对失败、停机和不确定状态保持可见。

不承诺秒级更新、完整历史、零遗漏或绝对不重复；来源自身延迟、Feed 窗口、网络与投递平台都会影响结果。

## 2. 版本边界

| 范围 | v0.1 | 后续 |
| --- | --- | --- |
| YouTube | 公共频道 Feed，频道 ID 与标准 `/channel/` 链接 | 按需解析 `@handle`、官方 API 补查、WebSub |
| 邮件 | 单 IMAP 账户、单文件夹、多条 Newsletter 匹配规则 | 多账户、OAuth、邮件转入接口 |
| 推送 | 独立飞书应用机器人向一个指定 open_id 私聊，每条内容一条通知 | 每日汇总、多目标、交互与群机器人 |
| 内容 | 原始元数据、必要邮件正文、安全预览 | 可选 Sift 摘要 |
| 部署 | 单用户、单持久化节点、单 Worker | 实测确有需要再扩容 |

非目标：完整邮箱客户端、自动回复邮件、公开视频下载、付费内容绕过、社交推荐、交易建议、知识库、多 Agent、公开多租户 SaaS。

## 3. 核心用户路径

### 3.1 频道更新

添加频道 → 检查连接与解析结果 → 展示首次运行规则 → 建立静默基线 → 定时发现新视频 → 保存条目和投递任务 → 飞书收到标题、简介、发布时间、视频链接。

首版不默认获取字幕。不能仅凭标题和简介宣称“已读完整视频”或提供视频全文摘要。

### 3.2 指定邮件

配置专用邮箱连接 → 测试授权 → 选择文件夹、发件地址和主题规则 → 显示匹配样例供用户核对 → 建立基线 → 发现新到达的匹配邮件 → 清理正文 → 飞书推送主题、来源、时间、正文预览。

默认不将邮件标为已读，不移动、删除或发送邮件。身份不符的邮件不入内容库；连接测试和诊断不得把整个邮箱正文拉取后展示。

### 3.3 失败处理

在更新记录中看到失败阶段和下一次重试时间 → 判断是配置、来源故障还是发送结果不明 → 修正配置或明确选择重发 → 保留结果与人工操作记录。

“手动检查”遵循原去重和首次基线规则，不等同于强制重复推送。

更新记录按内容时间倒序显示：邮件优先收件时间，视频/RSS使用发布时间，缺失时回退发现时间；后端先排序再分页，来源与状态筛选保持同一顺序（FR-08）。

## 4. v0.1 功能需求

| ID | 需求 | 验收行为 |

### 4.1 首次订阅与恢复

- v0.1 不提供自动历史回填。UI 明示“首次只建立基线，之后发现的新增条目才通知”。
- 频道基线记录当前可见视频 ID 和启用时间；不仅凭发布时间判断新增，避免不准的时间造成漏报。
- 邮箱规则记录启用时的 UID 边界；规则新增与账户扫描游标分别处理。启用后到达但 Date 较旧的邮件仍可算新邮件。
- 暂停来源时取消尚未执行的抓取与未发通知；已发消息无法自动撤回，正在发送的请求可能已经到达。
- 恢复来源时让用户选择“只接收恢复后的新内容”或“补查暂停期间仍可获取的内容”，默认前者；后者不保证完整历史。
- 删除最后一个引用来源后，条目不再用于待发送；共享于其他有效来源的条目仍保留，避免误删。

### 4.2 邮件匹配

- 首版采用地址精确匹配，域名大小写规范化；显示名不用于身份匹配，主题仅支持大小写不敏感的包含文本，不支持用户正则。
- 同一账户和文件夹内一封邮件匹配多条规则时，只形成一个内容条目和一次目标投递，保留来源关联。
- 发件人匹配不是身份认证；伪造发件人的风险仍需依赖邮箱服务商的反垃圾与认证结果。
- 转发后的外层发件人可能是用户本人，不能默认仍匹配原作者；连接预览必须明确展示匹配的字段，必要时改用独立文件夹和可核实的主题规则。
- 本项目只读 Newsletter，不自动打开确认订阅或退订链接、不执行邮件里的操作指令。
- 邮箱凭证不保证只有文件夹权限；推荐专用邮箱或服务商支持的最小授权方式。
- 为判断是否匹配，程序需要读取所选文件夹中新邮件的必要头部；即使不保存非匹配邮件，也发生了该读取。授权界面必须说明，不能声称凭证只能访问白名单发件人的邮件。

### 4.3 YouTube 能力边界

- 初版仅支持频道ID；当前按FR-20支持公开`@handle`解析为ID。仅添加保存时查询当前频道页的canonical/og:url，解析失败明示，不误取推荐项中的channelId；后续轮询固定ID，不追踪可变handle。
- 视频分类缺少可靠信息时显示“未分类”；不通过标题含 `live` 或时长猜测，承诺准确过滤直播或 Shorts。
- 不支持私有、会员专享及 Feed 未公开提供的视频。
- Feed 只提供有限近期条目，长期停机或高频频道可能超出窗口；必须显示覆盖不确定，不声称零遗漏。
- 条目后来不可访问时保留状态提示，不继续下载或绕过访问限制。

### 4.4 推送内容

| 来源 | 首版通知 |
| --- | --- |
| 视频 | 频道、标题、发布时间、原始简介预览、YouTube 链接 |
| 邮件 | Newsletter 名称、主题、发件来源、收件时间、正文预览 |

默认预览最多 400 个 Unicode 字符，按字符边界截断，不截断链接。邮件无可公开打开的原文 URL 时不伪造入口：默认提示“请在邮箱查看”，只有配置了可访问且鉴权的应用地址时才提供详情链接。

2026-10-16 用户已选择163邮箱和飞书应用机器人私聊。首版仅向配置的一个 open_id 出站发送，不读取通讯录、聊天历史或接收用户消息；不复用 CasePilot 凭证。启用邮件推送前预览外发字段并确认接收人。需要独立应用、最小发送权限、发布可用范围与本地 Secret 配置；这些真实接入尚未完成。

## 5. 页面与交互

### 5.1 订阅管理

来源列表展示名称、类型、状态、上次成功检查、待处理数量、最近错误。支持添加、连接测试、预览匹配、手动检查、暂停与删除。

添加邮件规则和启用推送是不同操作：先核对采集范围，再确认外发范围。连接失败允许保存为未启用，不启动调度。

### 5.2 更新与投递记录

按来源、投递状态筛选并分页，按内容时间倒序（收件/发布/发现回退）。列表展示标题、来源、摘要和投递状态、时间；较窄窗口将来源并入标题。独立详情使用可刷新的hash链接，展示视频入口、发布者简介或已获取字幕、结构化AI摘要与投递记录，不显示凭证。重发先核查，可能重复；脉络图是内容归纳，不表示因果关系。日期区间筛选暂不增加。

不要将“飞书接口确认接收”表述为“用户已经看到或阅读”。

### 5.3 设置

首版连接凭证由部署环境提供，界面只显示已配置/未配置、连接状态和可修改的非敏感参数；不做网页保存密钥或读回密钥。

设置页面包括默认时区、轮询间隔、发送上限、数据保留与备份说明。首版不提供多人注册、组织切换和复杂权限体系。

## 6. 默认参数与容量目标

以下是起始设计值，不是实测服务保证。具体参数需经过 M1/M4 测试再确认。

| 参数 | 设计默认值 |
| --- | --- |
| 时区 | Asia/Shanghai；数据库时间统一 UTC |
| 频道轮询 | 15 分钟，带随机抖动，限制最低间隔 |
| 邮箱轮询 | 5 分钟；不要只在预期到信时间检查一次 |
| 抓取并发 | 全局 2；同一账户/文件夹串行 |
| 发送并发 | 1；每轮最多 5 条 |
| 每日发送上限 | 50 条；以配置时区结算，超过后暂存并在后台告警 |
| 邮件正文保留 | 7 天；可配置缩短 |
| 普通条目与投递记录 | 30 天；未解决失败/未知记录不自动清除 |
| 最小去重标记 | 独立保留 90 天；再订阅仍需重新建立基线 |
| v0.1 验收规模 | 1 用户、10 频道、1 邮箱/文件夹、5 规则、1 飞书目标 |

用户主动选择的手动重发仍受发送上限约束，并纳入操作审计。超限提示优先在后台显示，不能为了通知超限而无限向同一故障目标发送告警。

## 7. 版本扩展需求

- FR-14 / v0.2：每日汇总、明确条目范围与不重复汇总规则。
- FR-15 / v0.2：通用 RSS/Atom、来源导入导出；只导出非敏感配置。
- FR-16 / v0.3：Sift 摘要、内容级调用缓存、摘要状态与总费用/请求预算。
- FR-17 / 待评估：多邮箱、飞书会话交互/群推送、YouTube WebSub 与官方 API 补查。
- FR-18 / 已完成接入前实验：隔离 yt-dlp、固定公开视频、匿名字幕验证；结果见 QUALITY_AND_RISKS 第11节，不等于生产所有视频可用。
- FR-19 / 可选字幕增强：用户2026-10-17确认收窄范围接入，见第11节；不扩大邮箱、模型与飞书真实调用授权。
- FR-20 / @频道入口：用户报告常见YouTube频道链接被拒绝，支持添加时受限解析并保存标准ID，见第12节。

这些需求在所属版本前不得以“顺手加上”为由进入首版。

## 8. v0.2 实施约定（2026-10-17）

用户要求继续开发 v0.2；这是候选版功能开发，不撤销 v0.1 真实联调与7天试运行门槛。

- FR-14：来源选择即时/日报。投递方式在内容首次排队时固定，切换只影响未来新条目；同一内容匹配多规则时优先即时，不双发。日报按发现时间纳入最近到期的本地时区窗口，默认10:30；迟到内容进入下一窗口。停机期间不逐天补发空日报，仅处理最近到期窗口内仍未分配的积压。
- 日报批次、成员、分片及消息快照在一个事务中冻结，最多每批500条，超出留到下一窗口。分片复用既有发送上限、重试和 unknown 处置；一个分片成功不代表整批成功。没有新内容只登记空批次，不发空消息。夏令时跳时采用 Luxon 向前归一后的时间，重复时段选择较早一次。
- 暂停/删除来源时，尚未冻结的内容正常取消；已冻结且尚未发送的受影响分片整体取消，不改写原分片或偷偷重发其中其他成员。界面明确提示此影响。发送中/已发消息无法撤回。任一成员正文过期，会清理该分片快照并阻止后续外发。
- FR-15：仅公共 HTTPS RSS/Atom，无账号、查询参数、片段、自定义端口或私有 Feed；暂不做 HTML 自动发现。请求时校验并固定 DNS 解析结果，禁止私有/特殊 IP；每次重定向重新检查，最多3次，响应限2MB，不下载条目链接。
- 配置导出只含来源定义与投递方式，无凭证、正文、状态或游标。RSS URL 默认不导出，只有用户明确确认 URL 公开且不含 Token 才包含。导入必须先预览、后确认；严格校验字段与数量，重复项跳过，整批事务落库，导入后均暂停且不自动推送。

以上不包含 AI 摘要、真实服务权限扩张或自动提交推送。

## 9. v0.3 实施约定（FR-16）

- 默认无模型运行。全局启用并确认总请求/人民币预算后，再分别授权来源为按需或自动。邮件将向 DeepSeek 外发已采集正文，视频默认外发 Feed 简介，RSS 仅外发 Feed 提供文本；不上传附件，不读取网页全文，不按标题推测视频。额外字幕范围须按FR-19重新授权。
- 使用部署者指定的可信本地 Sift 模块与独立 Key，固定 DeepSeek 端点。拒绝复用缺乏鉴权的公开 Sift 网页接口，不改动 Sift 仓库。第一版只接简洁模式，输入最多8000个UTF-16码元，过长明确失败而非静默截断；每任务最多2次模型请求（含一次校验修复），60秒总超时，无整任务自动重试。
- 自动摘要仅作用于来源授权后发现、非静默基线且已排队提醒的新增条目；不会批量外发已有收件箱或因元数据更新反复付费。按需可明确选择历史保留条目。相同条目/正文/标题/范围/模型/提示实现版本/来源授权代次复用结果；失败不会假装为缓存命中成功。
- 原始即时/日报不等摘要。AI结果在条目详情独立展示；可另行授权一条即时AI补充私聊，不改变或重新发送原消息，也不重写已冻结日报。补充消息使用既有发送限额和 unknown 核查；发送重试不重新生成摘要。已有摘要不因后来开启补充推送而自动外发。
- SQLite 原子预占每次HTTP调用的请求数和保守费用；失败、超时、修复均计数，不按成功数计预算。正文不入调用账本。价格由部署者按实际模型计费配置；使用请求UTF-8字节数作为保守输入token估值，加最大2600输出token，预算不退款。账本保留实际usage与估算占用，未知usage不视为免费；估算不是服务商账单保证。实测费用超过预占则停止全局摘要并要求重新核验价格。
- 预算为当前数据目录累计上限，不每日重置；只可显式确认调整，不删除历史使用量。来源暂停/编辑/删除、全局停用会撤销授权；排队取消、执行中尽力中止、旧结果与未发补充清理。已经发出的外部请求或飞书消息无法撤回。模型/实现/价格或飞书目标改变需重新确认全局及来源，旧任务不能悄悄向新接收人追加消息。
- 进程中断中的摘要转unknown，不自动重做；手动重试提示可能已计费。原文变化将旧摘要标为失效，不以旧缓存代表新内容。正文保留期同步清理摘要输入、结果和补充快照；恢复备份默认停用模型、撤销来源授权，待处理摘要须确认后重做。旧备份不包含备份后调用账单，应重新按服务商记录设置预算，不能据此承诺全历史费用准确。
- 引文存在校验不等于语义正确。UI保留范围、引文、状态和调用记录；合成固定案例人工核对事实、数字、日期与观点归属。未真实模型验证前不发布摘要准确率或真实费用结论。

## 11. 可选 YouTube 字幕（FR-19）

用户已确认继续接入，范围限定为：RSS仍负责发现更新和原通知；额外字幕任务复用现有摘要队列与账本，不另建平台或修改Sift仓库。

- 部署级默认关闭；逐频道选择feed/captions，并重新确认外发范围、按需/自动及独立AI补充。旧来源默认feed，授权版本升级后重新确认；导入/导出不包含新授权。自动仅处理授权后的新增提醒，不扫历史基线。
- 仅固定YouTube视频ID的公开匿名字幕，优先平台人工轨道（中/英文优先），再取原始自动轨道。记录语言、人工/自动类型、文本hash与时间戳；不读取Cookie、不下载媒体、不自动转写、不理解画面。直播不处理。
- 专用Python虚拟环境和锁定yt-dlp/EJS；显式Node运行时、受限环境、独立临时HOME；禁插件和远程组件获取。字幕响应流读取最多2MB、受限stdout、45秒子进程硬超时/取消并终止进程组。不落字幕文件；隔离不是操作系统级不可信代码沙箱，资源与网络总量仍需容器/主机限制。
- 文本含时间标记最多48000 UTF-16码元，视频最长4小时、最多20000条字幕；超限不静默截断。只移除相邻自动字幕的完全相同前缀，不承诺修复全部识别或重复错误。Sift按12000目标分块并合并，最多12次模型请求/4分钟总时间（含字幕获取）；每次分块/合并/修复继续受持久累计账本限制，不发布失败后的部分摘要。
- 复用summaries排队/领取/围栏，字幕缓存依附具体条目、范围、来源代次和实现版本；模型失败手动重试复用缓存并保留已花预算。简介与字幕互切清理旧结果和未发补充；暂停、删除、到期及备份恢复清理缓存。缓存不主动检测YouTube后来更改的字幕，重新授权并确认重新处理才会抓取。
- 原通知先执行且无需字幕成功；单Worker摘要仍可能延后下一轮最多4分钟，不承诺零延迟。无字幕、空字幕、网络、风控、超限分别记录，无自动重试，也不偷偷用简介代替视频内容。用户核查网络/字幕生成情况后手动重试。
- 展示摘要与对应字幕引文，并校验引文属于该时间单元；跳转链接由受控视频ID与时间生成，不采信模型URL。时间与自动识别可能不准确，引文存在不证明语义支持。真实模型、飞书和长期运行需单独验收。

## 12. YouTube @频道入口（FR-20）

- 接受标准频道ID、`/channel/UC…`、`@handle`、公开YouTube `https://…/@handle`，兼容常见频道分页路径与si/feature/sub_confirmation分享参数；不接受视频链接、任意主机、账号/自定义端口或跳转参数。仅构造固定www.youtube.com HTTPS请求，不原样打开输入URL。
- 添加保存前匿名读取频道页面canonical/og:url，结果必须唯一且为合法UC频道ID；用HTML解析器兼容YouTube将文档元信息放在body的情况。不执行页面JS、不搜索推荐项channelId、不读Cookie、不调用模型或依赖字幕组件。页面变动/不存在/风控/网络/4MB超限分别明示，不猜测ID。
- 查询15秒上限、拒绝自动重定向；保存完成后仍暂停，首次静默基线和原推送授权规则不变。不同别名解析到同一ID仍判重复；异步等待后再检查来源数量限制。
- `YOUTUBE_PROXY_URL`仅用于频道解析和YouTube RSS，默认直连；显式无账号HTTP(S)代理，不继承浏览器/系统代理，不影响其他适配器，字幕仍有独立配置。不降低TLS校验。
- 演示模式不访问真实频道，明确返回演示限制；仅`@feedrelay-demo`映射到合成频道。配置导入/导出保持标准ID，不在导入预览时访问YouTube。该增强不需要schema升级、不新增任何外部凭证或模型预算授权。
